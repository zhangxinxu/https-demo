手风琴 Accordion 高度动画

同一个页面给出三种实现，外观与动画曲线保持一致：JS 驱动的 grid-template-rows，以及原生 <details name> 的两种高度动画写法。

方式一div + grid-template-rows（JS 控制状态）

传统做法是用 max-height 过渡，但内容高度未知时只能猜一个足够大的值，导致收起时前半段几乎看不到动画。

0fr 到 1fr 是数值插值，浏览器能算出真实高度，所以展开和收起的时长与曲线完全一致。

grid 行高塌陷到 0 时，子元素的内容不会自己消失，仍然会溢出到面板外面。

给直接子元素设置 overflow: hidden 与 min-height: 0，才能真正把内容裁掉，让高度动画看起来是"收进去"的。

只做两件事：切换父级 .item 的 is-open 类，以及同步 aria-expanded 状态。

高度、透明度、图标旋转全部由 CSS 过渡完成，没有逐帧计算，也没有读取布局属性，性能开销极小。

当前是"多开模式"，每个面板互相独立。若要做成"一次只开一个"，在打开某一项时先把其他项的 is-open 移除即可。

标题使用原生 <button>，因此回车、空格都能操作，Tab 也能正常聚焦。

方式二details + name（原生互斥，零 JS）

01 details + name 算是「原生手风琴」吗？

<summary> 天然就是可点击的标题，点击切换父级 <details> 的 open 状态，展开收起由浏览器负责。

而 name 属性会让同名的一组 <details> 互斥：打开其中一个，其余自动关闭。整套交互不需要一行 JS。

02 details 的高度动画是从哪来的？

内容区由 ::details-content 伪元素表示。给它设置 block-size: 0 与 overflow: hidden，展开时切到 block-size: auto。

关键在于 interpolate-size: allow-keywords，它允许 0 与 auto 这类关键字尺寸参与插值；再配合 transition-behavior: allow-discrete 让 content-visibility 延迟隐藏，收起时内容不会瞬间消失。

03 name 属性的互斥规则是怎样的？

同名的 details 同一时间最多只有一个处于展开状态；点击已展开的那一项，可以把它重新关上，也就是允许全部收起。

本例中四个面板使用了同一个 name="faq-native"，所以它们彼此互斥，与上方「多处同时展开」的方式一形成对比。

04 这种方式有什么取舍？

优点是语义完整、无 JS 也能工作，禁用脚本或纯静态文档场景下依然可交互，同时天然支持页内搜索与打印展开。

代价是高度动画依赖 ::details-content 与 interpolate-size 这两项较新的 CSS 能力，老浏览器里会退化为瞬时切换——功能不受影响，只是没有过渡效果。

方式三details + name + grid-template-rows（0fr → 1fr）

01 details 的内容区可以直接当 grid 容器用吗？

::details-content 本身就是包住展开内容的容器，给它 display: grid 加 grid-template-rows: 0fr，展开时切到 1fr 即可。

与第一个案例的唯一区别是：这里的 grid 容器不是自己写的 div，而是浏览器提供的伪元素。

02 内层的 overflow: hidden 还需要吗？

需要。行高塌陷到 0 只是把 grid 轨道压扁，内容本身仍会溢出到面板外面，视觉上会"露出来"。

所以要在 ::details-content 的唯一子元素上设置 overflow: hidden 和 min-height: 0，让内容被真正裁掉，这正是第一个案例的 .panel-inner 所做的事。

03 和方式二的 block-size 方案有什么差别？

方式二依赖 interpolate-size: allow-keywords，让 0 与 auto 之间也能插值；方式三是 0fr 与 1fr 之间的纯数值插值，不需要关键字尺寸支持。

两者都要处理 content-visibility 的离散切换，否则收起瞬间内容会直接消失，高度动画就看不到了。

04 为什么要把 name 分组错开？

方式二用的是 name="faq-native"，这里用 name="faq-grid"。分组名一旦相同，两组就会合并成同一互斥组，点击会互相干扰。

因此每个演示区块要使用自己的 name 值，保证互斥范围只在本组内生效。

三种实现共用一套视觉样式，差别只在动画载体：案例一是 div + grid-template-rows，案例二是 ::details-content + block-size: auto，案例三是 ::details-content + grid-template-rows。状态分别由 is-open 类与 [open] 属性驱动。
